# Documentation site workspace

## Context

`apps/docs` hosts the public documentation site (Docusaurus). It must serve three
content sets with different lifecycles: operator guides (never versioned), the protocol
specification and the SDK documentation (both versioned). The overall design is in
`backlog/features/documentation-site/technical.md`; this page records the choices made
while scaffolding the workspace.

## Decision

- **Three docs instances in one site**: the classic preset carries the default instance
  with id `guides` (`docs/`, route `/guides`, never versioned); two extra
  `@docusaurus/plugin-content-docs` instances `protocol` and `sdk` each get their own
  path, route base, sidebar and version dropdown.
- **Local search** through `@easyops-cn/docusaurus-search-local` over the three route
  bases. Because the default instance is not called `default`, the theme option
  `docsPluginIdForPreferredVersion: 'guides'` is required: without it the search bar
  hook looks up a plugin id that does not exist and static generation of `/404.html`
  and `/search` fails.
- **Not an ES module package**: `apps/docs/package.json` has no `"type": "module"`.
  Docusaurus generates `.docusaurus/registry.js` using `require.resolveWeak`, which
  webpack does not parse when the package is typed as ESM, and the server bundle then
  crashes. Config, sidebars and tests are TypeScript, so nothing else depends on it.
- **Explicit dependencies** on `@docusaurus/plugin-content-docs` and `@mdx-js/react`:
  with Bun's isolated installs Docusaurus cannot resolve them transitively.
- **Root redirect**: `src/pages/index.tsx` redirects `/` to `/guides/intro`.
- **Private workspace**: `"private": true`, so Changesets ignores it; the CHANGELOG is
  maintained by hand under `## [Unreleased]`, like the other apps.
- **Tests**: a Vitest project (`apps/docs/vitest.config.ts`, registered in the root
  `vitest.config.ts`) asserts the shape of `docusaurus.config.ts`. The real check of the
  site is `bun run --filter '@ekozhq/docs' build`, which also fails on broken links.

## Protocol instance sourcing

- **Single source of truth**: the `protocol` instance reads `../../docs/protocol`
  directly (`path` of its docs plugin), like TypeDoc reads `packages/sdk`. There is no
  copy, so the published text cannot drift from the specification. `docs/protocol/*.md`
  is therefore written to be published as is: no issue numbers, no `apps/server`,
  `backlog/` or `docs/technical` links, no "draft ahead of the server" wording.
  A test guards this.
- `docs/protocol/README.md` is the overview page (front matter `slug: /`, so the route is
  `/protocol/`) and stays the repository entry point. `docs/protocol/CHANGELOG.md` is
  published as is, so it is kept condensed and grouped by page, without issue
  references. Versioning follows that changelog and is
  automated (see [Automatic versioning](#automatic-versioning)).
- The sidebar is an explicit ordered list (reading order), not autogenerated, and a
  test checks that every page of `docs/protocol` is listed, that no file is orphaned and
  that no internal reference leaks.
- **`markdown.format: 'detect'`**: the specification uses raw `<major>`, `<keyId, ...>`
  and `{ ... }` in prose and tables, which MDX rejects. `.md` files are therefore parsed
  as CommonMark (MDX stays available for `.mdx`). `onBrokenAnchors: 'throw'` was added
  so the many cross-page anchors are verified by the build.

## SDK API reference (TypeDoc)

- **Generated at build time** by `docusaurus-plugin-typedoc` (with `typedoc` and
  `typedoc-plugin-markdown`, versions pinned to the peer ranges of the plugin), which
  runs TypeDoc from `packages/sdk/src/index.ts` when Docusaurus loads its plugins. The
  SDK does not need to be built first: TypeDoc reads the sources.
- **Output inside the `sdk` instance tree** (`out: 'sdk/api'`), so that a version
  freeze (see [Automatic versioning](#automatic-versioning)) freezes the generated reference with the
  guides. `sdk/api/` is git-ignored; only the frozen copies under `sdk_versioned_docs/`
  are committed.
- **`docsPath: './sdk'` is required**: the plugin defaults it to the classic preset path
  (`docs`, the guides instance), which would make the generated sidebar ids point at the
  wrong instance (`../sdk/api/...`) and fail the build.
- **Sidebar**: `sidebars-sdk.ts` requires the generated `sdk/api/typedoc-sidebar.cjs`
  (written before sidebars are loaded) and nests it under an "API reference" category
  linked to `api/index`. The sidebar module therefore cannot be imported by a test on a
  clean checkout, so tests assert on its source text.
- **`logLevel: 'Error'`**: the generated wire types carry validation tags (`@pattern`,
  `@minLength`, ...) that TypeDoc reports as unknown block tags, hundreds of warnings
  that hide real problems.
- Guide pages use the published name `@ekozhq/sdk` (the package README still says
  `@ekoz/sdk`).

## Deployment (GitHub Pages)

- **Dedicated workflow** `.github/workflows/docs.yml`, independent from `ci.yml`: it is
  not part of the required `check` status, so a docs failure never blocks a merge.
- **Triggers**: push on `develop` limited to `apps/docs/**`, `packages/sdk/src/**`,
  `docs/protocol/**` and the workflow itself, plus `workflow_dispatch`. Never on pull
  requests.
- **Jobs**: `build` (shared `./.github/actions/setup`, which also builds the SDK, then
  `bun run --filter '@ekozhq/docs' build`, then `actions/upload-pages-artifact@v3` on
  `apps/docs/build`) and `deploy` (`actions/deploy-pages@v4`, environment
  `github-pages`). `concurrency: pages` without cancellation avoids interrupting a
  running deployment.
- **Custom domain**: `apps/docs/static/CNAME` (`ekoz.marmotz.dev`), copied to the
  build root by Docusaurus.
- **Manual steps outside the repo** (not scripted): Settings > Pages > source "GitHub
  Actions"; custom domain and "Enforce HTTPS"; a DNS `CNAME` record for
  `ekoz.marmotz.dev` pointing to `marmotz.github.io`.

## Changelog gate

`scripts/check-changelog.sh` includes `apps/docs` in its app loop. Since the site has
almost no `src/` (only CSS and a redirect page), the docs "source" that requires an
`## [Unreleased]` entry in `apps/docs/CHANGELOG.md` is `src/`, `docs/` and
`sdk/` (`sdk/api/` is generated and git-ignored). `test/` and `*.test.*` files never
count. `scripts/check-changelog.test.ts` covers these cases.

## Automatic versioning

The `sdk` and `protocol` instances are versioned independently, by
`apps/docs/scripts/version-docs.ts` (`bun run docs:version`, `--check` to only verify):

- **SDK**: the version is `packages/sdk/package.json`, frozen as `major.minor` (patch
  releases reuse the minor's docs). `0.0.0` means unreleased, nothing is frozen.
- **Protocol**: the version is the first released heading (`## [x.y.z]`) of
  `docs/protocol/CHANGELOG.md`, frozen as `major`, or `0.minor` while the major is 0
  (minors may still break there). It follows the protocol major, not the SDK.
- The script runs `docusaurus docs:version:<instance> <label>` only when the label is
  missing from `<instance>_versions.json`, so it is idempotent. The snapshot is committed
  (`*_versioned_docs`, `*_versioned_sidebars`, `*_versions.json`) and, for the SDK, includes
  the generated TypeDoc reference, which freezes the API with the guides.
- `bun run release:version` runs `changeset version` then the script, so the version PR
  carries the snapshot. `apps/docs/test/versions.test.ts` fails when a released version has
  no snapshot, which catches a forgotten protocol release (protocol has no npm publish
  step to hook into).
- Why snapshots are committed and not generated at build time: a build-time snapshot
  would copy the latest docs under an old label, so old versions would drift forward.

## Alternatives considered

- One docs instance with three top-level folders: rejected, versions are per instance
  and Guides must never be frozen.
- Hand-adapted copy of `docs/protocol` in `apps/docs/protocol/` (first implementation):
  rejected, two texts drifted apart and every specification change had to be ported by
  hand. Build-time copy or symlink: unnecessary, the plugin can read the directory.
- A custom search plugin or Algolia: rejected, local search needs no external service.

## Consequences

- Content tasks fill `docs/`, `protocol/` and `sdk/guide/`; each placeholder `intro.md`
  is replaced by real content.
- Adding a fourth instance requires adding its route base to the search theme options.
