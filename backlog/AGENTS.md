# AGENTS.md — `backlog/`

One backlog for the whole monorepo. Product scoping (`overview.md`) and
technical design (`technical.md`) live here, versioned with the code.
Implementation tasks are **GitHub issues** in `marmotz/ekoz`. Run the
`backlog-*` skills and `implement-issue` **from the repo root**.

**Backlog mode** : github-only

GitHub issues are the single source of truth for implementation work. There is
no `backlog/tasks/` directory. `backlog/todo.md` is a **read-only generated
artifact** — a projection of the issues produced by the `backlog-sync` skill;
nobody edits it or ticks a box by hand.

Global documentation — functional specification, protocol, technical design —
lives in [`../docs/`](../docs/).

## Structure

- `features/<slug>/overview.md` — product scoping (via `backlog-discuss`).
- `features/<slug>/technical.md` — design grounded in the code (via `backlog-technical`).
- `todo.md` — generated by `backlog-sync`, one section per feature, delivery order.
- GitHub issues — created in **`marmotz/ekoz`** (issues and PRs share one sequence).

## Conventions

- Everything in **English**: directories, files, identifiers, comments. The
  `backlog-*` skill templates use French field names; use the English
  equivalents (`**Status**` / `todo` / `in progress` / `done`,
  `## Verified findings`, `## To do`, `## Dependencies`).
- **Issue → feature linkage**: an issue carries the label `feature:<slug>`,
  where `<slug>` is the `backlog/features/<slug>/` folder name. Issues with no
  such label land in the `## No feature` section of `todo.md`.
- **Dependencies between issues**: `Depends on #N` lines in the issue body (or
  `Depends on <owner>/<repo>#N` cross-repo). `implement-issue` blocks on open
  dependencies by scanning for that exact pattern.
- **Issue bodies are self-contained**: they repeat the task content and link
  repo files by **absolute URL**
  (`https://github.com/marmotz/ekoz/blob/develop/...`). A task whose code change
  lands in a specific workspace notes it in the body; the issue still lives in
  `marmotz/ekoz`.

## Design decisions

Design decisions are written up as prose pages under
[`../docs/technical/`](../docs/technical/) (context, alternatives, consequences),
not as ADRs. See [`../CONTRIBUTING.md`](../CONTRIBUTING.md). Changelog discipline
is also there.
