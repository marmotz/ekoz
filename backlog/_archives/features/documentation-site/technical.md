# Documentation site — technical design

Grounded in the current state of the repo (root [package.json](../../../../package.json),
[biome.json](../../../../biome.json), [lefthook.yml](../../../../lefthook.yml),
[.github/workflows/ci.yml](../../../../.github/workflows/ci.yml),
[scripts/check-changelog.sh](../../../../scripts/check-changelog.sh),
[scripts/release-publish.sh](../../../../scripts/release-publish.sh),
[.changeset/config.json](../../../../.changeset/config.json)) and on the sibling
Docusaurus setup at
[`marmotz/kurotako` `apps/docs`](https://github.com/marmotz/kurotako/tree/develop/apps/docs),
reused as the reference implementation for config, TypeDoc wiring, local search and the
GitHub Pages deploy workflow.

## New workspace: `apps/docs`

Added to the `apps/*` workspace glob in [package.json](../../../../package.json) (already
matches, no change needed there). Not published to npm (`"private": true`), so it needs
no entry in `.changeset/config.json`'s `ignore` list — that list is only consulted for
workspaces Changesets would otherwise try to version, and a private package without a
changeset is silently skipped.

```
apps/docs/
  package.json
  docusaurus.config.ts
  sidebars.ts                  # sidebar for the default ("guides") instance
  tsconfig.json
  docs/                        # default instance: "Guides" — NOT versioned
    intro.md
    getting-started/
      quickstart.md
      installation.md
    server/
      deployment.md
      configuration.md
      operations.md
    security.md
    faq.md
  # instance id "protocol": versioned, no local folder, reads ../../docs/protocol
  sdk/                          # instance id "sdk" — versioned
    guide/
      quickstart.md
      auth.md
      realtime.md
    api/                        # generated by docusaurus-plugin-typedoc, git-ignored for `next`
  protocol_versioned_docs/       # created by `docusaurus docs:version:protocol <x.y>`
  protocol_versioned_sidebars/
  protocol_versions.json
  sdk_versioned_docs/            # created by `docusaurus docs:version:sdk <x.y>`
  sdk_versioned_sidebars/
  sdk_versions.json
  src/css/custom.css
  static/
    img/
    CNAME                        # "ekoz.marmotz.dev"
  CHANGELOG.md
```

`docs/`, `protocol/` and `sdk/` are the **unversioned working copies** — what `next`
serves and what `docs:version:<id>` freezes into `<id>_versioned_docs/<version>/` on a
version cut. The default instance (`docs/`) is deliberately never cut: guides always
describe the latest deployable server.

## `docusaurus.config.ts` — three docs-plugin instances

One Docusaurus site, one `preset-classic` default instance (Guides), plus two extra
`@docusaurus/plugin-content-docs` instances (Protocol, SDK). This is the documented
[multi-instance pattern](https://docusaurus.io/docs/next/docs-multi-instance): each
extra instance gets its own `id`, `path`, `routeBasePath` and therefore its own
`<id>_versions.json` / `<id>_versioned_docs/` / independent version dropdown.

```typescript
const config: Config = {
  title: 'Ekoz',
  url: 'https://ekoz.marmotz.dev',
  baseUrl: '/',
  organizationName: 'marmotz',
  projectName: 'ekoz',

  presets: [
    ['classic', {
      docs: {
        id: 'guides',
        path: 'docs',
        routeBasePath: 'guides',
        sidebarPath: './sidebars.ts',
        // no `versions` config here -> this instance is never cut.
      },
      blog: false,
      theme: { customCss: './src/css/custom.css' },
    } satisfies Preset.Options],
  ],

  plugins: [
    ['@docusaurus/plugin-content-docs', {
      id: 'protocol',
      path: 'protocol',
      routeBasePath: 'protocol',
      sidebarPath: './sidebars-protocol.ts',
    }],
    ['@docusaurus/plugin-content-docs', {
      id: 'sdk',
      path: 'sdk',
      routeBasePath: 'sdk',
      sidebarPath: './sidebars-sdk.ts',
    }],
    ['docusaurus-plugin-typedoc', {
      id: 'sdk-api',
      entryPoints: ['../../packages/sdk/src/index.ts'],
      tsconfig: '../../packages/sdk/tsconfig.json',
      out: '../sdk/api',              // writes into the "sdk" instance's tree
      readme: 'none',
      hidePageHeader: true,
      hideBreadcrumbs: true,
      sidebar: { autoConfiguration: true, pretty: true },
    }],
  ],

  themes: [
    ['@easyops-cn/docusaurus-search-local', {
      hashed: true,
      indexDocs: true,
      indexBlog: false,
      docsRouteBasePath: ['/guides', '/protocol', '/sdk'],
    }],
  ],

  themeConfig: {
    navbar: {
      items: [
        { type: 'docSidebar', sidebarId: 'guides', docsPluginId: 'guides', label: 'Guides' },
        { type: 'docSidebar', sidebarId: 'protocol', docsPluginId: 'protocol', label: 'Protocol' },
        { type: 'docSidebar', sidebarId: 'sdk', docsPluginId: 'sdk', label: 'SDK' },
        { type: 'docsVersionDropdown', docsPluginId: 'protocol', position: 'right' },
        { type: 'docsVersionDropdown', docsPluginId: 'sdk', position: 'right' },
      ],
    },
  },
};
```

Home page (`/`) redirects to `/guides/intro` via `presets[0].docs.routeBasePath` left as
`guides` (not `/`, unlike Kurotako's single-instance site) — a small custom `src/pages/index.tsx`
doing a client-side redirect, or a static HTML redirect in `static/index.html`, whichever
proves simpler once the site is scaffolded; not a design decision that needs settling now.

**Why TypeDoc output isn't a fourth plugin instance**: `docusaurus-plugin-typedoc` just
writes markdown files into a target folder (`out: '../sdk/api'`); those files are picked
up by the *sdk* docs instance like any hand-written page, so a normal version cut of
`sdk` freezes the last-generated API markdown into `sdk_versioned_docs/<version>/api/`
along with everything else. No independent versioning logic needed for the API pages.

## Content sourcing — reuse vs. duplicate

`docs/protocol/*.md` and `docs/technical/*.md` at the repo root stay the source of
truth. The `protocol` instance is **not** a copy: its docs plugin `path` points at
`../../docs/protocol`, so the published spec is the repository spec, written to be
publishable as is (no issue numbers, no `apps/server` or `docs/technical` links).
`docs/protocol/README.md` is the overview page and `CHANGELOG.md` the changelog page. A
hand-adapted copy in `apps/docs/protocol/` was tried first and rejected because it
drifted (see [docs-site-workspace](../../../../docs/technical/docs-site-workspace.md)).
`docs/technical/*.md` is not published.

`apps/docs/sdk/guide/*.md` are new, hand-written usage guides — nothing to migrate from.
`apps/docs/docs/*` (Guides instance) are new pages; `installation.md` /
`configuration.md` / `operations.md` draw on
[apps/server/README.md](../../../../apps/server/README.md) and
[apps/server/compose.yaml](../../../../apps/server/compose.yaml) (docker compose) for
accuracy, not on `docs/technical/` (internal design rationale, not operator-facing).

## Versioning workflow (manual)

No automation in `scripts/release-publish.sh`. At release time:

- **Protocol**: after updating `docs/protocol/CHANGELOG.md` with a new version heading,
  run `bun run --filter '@ekozhq/docs' docusaurus docs:version:protocol <x.y>` from
  `apps/docs`. This copies `docs/protocol/` into `protocol_versioned_docs/<x.y>/` and appends
  `<x.y>` to `protocol_versions.json`.
- **SDK**: after `bun run release` publishes `@ekozhq/sdk@<x.y.z>` to npm, run
  `docusaurus docs:version:sdk <x.y>` (minor precision, matching how the protocol is
  versioned — a patch release of the SDK doesn't need its own doc snapshot unless it
  changes public API surface).
- **Guides**: never cut.

This is a manual step a maintainer runs; not wired into `release-publish.sh` per the
decision above (keeps the release script's blast radius to npm publishing only).

## CI / deployment

Dedicated workflow `.github/workflows/docs.yml`, modeled on
[`marmotz/kurotako`'s equivalent](https://github.com/marmotz/kurotako/blob/develop/.github/workflows/docs.yml):

```yaml
name: docs

on:
  push:
    branches: [develop]
    paths:
      - 'apps/docs/**'
      - 'packages/sdk/src/**'
      - 'docs/protocol/**'
      - '.github/workflows/docs.yml'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: ./.github/actions/setup
      - run: bun run --filter '@ekozhq/docs' build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: apps/docs/build

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Independent of `ci.yml`'s `check` job (the required status for branch protection) — a
docs build failure never blocks a code PR, and a code PR never has to wait on a docs
build. Runs only on push to `develop` (this repo's deploy branch, confirmed in
`ci.yml`), not on `main` or on pull requests: docs deploy is a push-to-production action,
not a PR gate.

**GitHub Pages setup** (one-time, done by a maintainer, not part of any script in this
repo): repo Settings → Pages → source "GitHub Actions"; add custom domain
`ekoz.marmotz.dev` (matches `static/CNAME`); enable "Enforce HTTPS"; add the DNS
`CNAME` record pointing `ekoz.marmotz.dev` at `marmotz.github.io` in whichever DNS
zone hosts `marmotz.dev` (outside this repo's scope).

## Changelog discipline

`apps/docs` is an `apps/*` workspace, so it falls under
[scripts/check-changelog.sh](../../../../scripts/check-changelog.sh)'s existing loop
(`for app in apps/admin apps/client-web apps/server`) — **that loop needs
`apps/docs` added**, or a change to `apps/docs/src` (its actual `src/`, if any custom
React bits are added later) would silently skip the changelog gate. `apps/docs/CHANGELOG.md`
follows the same `## [Unreleased]` convention as the other apps.

## lint:boundaries / lint / typecheck

- `apps/docs` needs its own `tsconfig.json` (`tsc --noEmit` as its `typecheck` script,
  matching every other workspace) so it's covered by the root `bun run typecheck`
  (`bun run --filter '*' typecheck'`) without extra wiring.
- No `eslint-plugin-boundaries` needed — that rule protects feature-module isolation in
  `apps/server`, `apps/admin`, `apps/client-web`; `apps/docs` has no feature modules.
  Root `bun run lint:boundaries` stays a fixed three-app list and needs no change.
- Biome formats `apps/docs/**/*.{ts,tsx,json}` under the existing root `biome.json`
  (its `files.includes` excludes list doesn't need a new entry — TypeDoc's generated
  `sdk/api/*.md` are markdown, already outside Biome's scope, and are git-ignored for
  the `next` (unversioned) copy; only the frozen `sdk_versioned_docs/**/api/*.md` are
  committed, and Biome does not touch markdown content today).

## Consequences / what doesn't change

- `docs/` at the repo root, `backlog/`, `CONTRIBUTING.md` conventions: unchanged. This
  feature adds a *consumer* of `docs/protocol/` and `docs/technical/`, not a replacement.
- `scripts/release-publish.sh`: unchanged (per the decision above).
- `.changeset/config.json`: unchanged (`apps/docs` is private, already outside
  Changesets' concern; no entry needed in `ignore`).
- `scripts/check-changelog.sh`: **one-line change** — add `apps/docs` to the `for app in
  ...` loop. Flagged here for the implementation task; not applied in this design phase.
